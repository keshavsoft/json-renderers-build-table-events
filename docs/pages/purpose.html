Design Philosophy

What is the Purpose?

Learn why this library exists, the monolithic problems it eliminates, and why decoupling table rendering from event orchestration matters.

🎯 Primary Goal

The fundamental purpose of json-renderers-build-table-events is to provide a declarative, framework-agnostic interactivity and event routing layer for table components.

In modern web development, tables are rarely static. Users need to search across records, click rows for details, trigger row-level operations (view, edit, delete), and add new records from table footers. However, managing all of these interactions inside the same module that renders table HTML creates severe maintainability and UX problems.

The Monolithic Problem

Historically, table builders bundled both markup generation and event wiring together. This caused three major issues:

1. Destruction of Input Focus

When a user typed a character into a search input, the component would re-render the entire table container to reflect filtered rows. In doing so, the search input itself was removed and recreated in the DOM, instantly stripping keyboard focus. Users had to re-click the search input after every single keystroke.

2. Brittle, Fragile DOM Selectors

Developers wrote hardcoded IDs (e.g. document.getElementById('my-save-btn')) or brittle parent traversals (e.target.parentNode.parentNode.querySelector('td')). A small CSS or layout change would silently break event handlers.

3. Memory Leaks and Listener Overhead

Attaching individual click listeners to hundreds of rows or action buttons multiplied memory consumption and created event listener bloat.

The Decoupled Solution

This library establishes an architectural separation between rendering and events:

  • Pure Rendering: A renderer (such as json-renderers-build-table) is responsible only for turning JSON into table markup.
  • Decoupled Event Orchestration: json-renderers-build-table-events listens at the container level and routes interactions to declarative actions.
  • Targeted Row Repainting: During search filtering, only the inner table rows or tbody are repainted. The search bar remains untouched in the DOM, so user typing focus is never lost.
  • Zero Hardcoded JS Selectors: All traversals are specified in serializable JSON instruction sets executed by dom-primitive-engine.
