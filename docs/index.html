Instruction-Driven Event Layer

json-renderers-build-table-events

Decoupled, instruction-driven event orchestration and declarative DOM traversal for table components.

📖 The Story of This Repository

Why this package was created and how it solves real-world table interactivity problems.

Chapter 01 The Monolithic Problem

The Day the Search Box Lost Its Mind

Imagine you are building a data-rich web table. You have records to display, columns to configure, and a live search input at the top. When a user types "Bolt", you want the table to immediately filter down to matching bolts.

In early implementations, table components were built as a single monolith. The code that created HTML elements also handled search typing, row selection, and button clicks. Whenever the search filter changed, the entire table component wiped its DOM and re-rendered itself from scratch.

The Focus Destruction Bug: Because the entire component was destroyed on each keystroke, the search input field was wiped from the DOM. The user typed B, and suddenly their cursor vanished! They had to reach for the mouse, click the search box again, type o, lose focus again, and click back. It was an infuriating user experience.

On top of that, JavaScript files were cluttered with brittle, hardcoded selectors like document.getElementById('my-save-btn') and fragile DOM walking chains like event.target.parentElement.parentElement.children[2]. If a designer added a wrapper <div>, the entire application broke.

Chapter 02 The Separation Insight

The Discovery: Divide and Conquer

The realization was simple but profound: Rendering HTML and Orchestrating Events are two completely different jobs.

We decided to separate them into two clean, independent layers:

1. Pure Rendering

Responsible only for taking raw data and returning clean HTML tables (e.g. json-renderers-build-table). It does not care about event listeners or click handlers.

2. Event Orchestration

json-renderers-build-table-events: Attaches once at the container level. It manages typing, row selection, row actions, and record saving without touching the renderer's internals.

By making this separation, live searches re-render only the inner table rows (tbody). The search bar sitting above the table is never touched, so the user can type at full speed without ever losing keyboard focus.

Chapter 03 The Breakthrough

Instruction-Driven Traversal

Rather than writing hardcoded DOM query selectors inside JavaScript functions, all element lookups and traversals are specified declaratively using JSON instruction recipes executed by dom-primitive-engine.

  • Zero Memory Leaks: A single delegated listener on the container handles thousands of rows effortlessly.
  • No Hardcoded JS Selectors: Element traversals are declarative recipes, making the UI resilient to HTML refactoring.
  • Framework Agnostic: Works seamlessly with Vanilla JS, React, Vue, or any server-rendered template.

That is why json-renderers-build-table-events exists: to turn messy, focus-destroying table event code into a clean, smooth, and robust experience for both developers and users.
